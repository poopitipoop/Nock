QUESTION 2: Once the Hoon consensus wiring is complete, would a hyperscaler
running Pearl's vLLM plugin automatically also mine Nockchain — or would they
need to separately install, configure and run the ai-pow-miner binary? Show the
exact code path that proves this.
================================================================================

ANSWER: They would need to separately install, configure, and run the
ai-pow-mine binary. It is NOT automatic.

Pearl's vLLM plugin exposes the Gateway JSON-RPC endpoint. That is all Pearl
does from Nockchain's perspective. The ai-pow-mine binary is an entirely
separate OS process that must be explicitly started. It connects to TWO
separate services on startup and coordinates between them:

  1. The Nockchain node (gRPC) — to get block candidates and submit solutions
  2. The Pearl Gateway (JSON-RPC) — to get Pearl block headers

Neither service starts the other. Neither service starts ai-pow-mine.

  pub async fn run(cfg: MinerConfig, shutdown: CancellationToken)
      -> Result<(), MinerError>
  {
      cfg.validate()?;
      cfg.puzzle.validate_canonical_submission_ready()?;

      loop {
          // Step 1: Connect to Nockchain node via gRPC
          let mut client = match NodeClient::connect(&cfg.node_addr).await {
              Ok(c) => { ... c }
              Err(e) => {
                  consecutive_failures += 1;
                  ...
                  if consecutive_failures >= cfg.reconnect_max_attempts {
                      return Err(MinerError::TooManyReconnects { count: ... });
                  }
                  ...
              }
          };

          // Step 2: Push Nockchain wallet address to node kernel
          if let Err(e) = client
              .set_mining_key(
                  AiPowMinerWire::SetPubKey.to_wire(),
                  Vec::new(),
                  cfg.mining_pkh_configs.clone(),
              )
              .await
          {
              return Err(MinerError::Configure(format!("set_mining_key: {e}")));
          }

          // Step 3: Subscribe to %mine-ai candidate effects from Nockchain node
          let mut candidates = match client
              .watch_candidates(vec![b"mine-ai".to_vec()])
              .await { ... };

          // Step 4: Enable mining on node
          if let Err(e) = client
              .enable_mining(AiPowMinerWire::Enable.to_wire(), true)
              .await
          {
              return Err(MinerError::Configure(format!("enable_mining(true): {e}")));
          }

QUESTION 4: Can Nockchain bundle their miner into Pearl's vLLM plugin without
Pearl's team cooperation — is there anything in the code that would prevent or
require Pearl's involvement?
================================================================================

ANSWER: Nockchain cannot unilaterally bundle INTO Pearl's vLLM plugin (they
don't have Pearl's source code). However, the interface boundary is extremely
narrow — just two JSON-RPC methods — so the miner runs as a separate process
alongside Pearl's plugin with minimal integration surface.

BUT: Pearl's cooperation on the Gateway API is REQUIRED for merge mining to
work at all. Specifically, Pearl's Gateway must implement:

  1. getMiningInfo with coinbase_aux_flags and return_aux_inclusion parameters
  2. submitPlainProof

If Pearl does not implement these parameters, merge mining breaks.

Summary of what requires Pearl's cooperation:
  - Pearl's Gateway must accept coinbase_aux_flags in getMiningInfo params
  - Pearl's Gateway must return aux_inclusion in getMiningInfo response
  - Pearl's Gateway must implement submitPlainProof to accept plain proofs
  - Pearl's coinbase transaction format must support embedding the
    "NOCKCHAIN-AI-POW-AUX" commitment in the input script (txid-committed,
    not witness)

Without Pearl building these features into their Gateway, the miner errors
out on every single Nockchain candidate and never mines a block.

QUESTION 5: What exactly does the miner need to run simultaneously for merge
mining to work? List every process/binary that must be running.
================================================================================

ANSWER: Three processes, all required simultaneously.

  PROCESS 1: nockchain node
    What:    Nockchain full node with private gRPC interface enabled
    Default: http://127.0.0.1:5555
    CLI arg: --node-addr <URL>
    Role:    Emits %mine-ai block candidates; receives %ai-pow solution pokes;
             advances the Nockchain chain

  PROCESS 2: Pearl Gateway server
    What:    Pearl's software exposing getMiningInfo + submitPlainProof JSON-RPC
    Default: unix:/tmp/pearlgw.sock  (or TCP)
    CLI arg: --pearl-gateway <ENDPOINT>
    Role:    Provides Pearl block header (sigma) per refresh interval;
             accepts Pearl PlainProof submissions; is part of Pearl's
             infrastructure (likely the vLLM plugin or a sidecar)

  PROCESS 3: ai-pow-mine binary
    What:    Nockchain's standalone miner
    CLI:     ai-pow-mine --mining-pkh <NOCKCHAIN_WALLET_HASH>
    Role:    Coordinates between processes 1 and 2; runs the matmul search;
             builds the 3-layer ZK recursive certificate; submits to both

WHAT BREAKS IF ANY PROCESS IS MISSING:

  No Nockchain node:
    NodeClient::connect fails -> MinerError::TooManyReconnects after 5 retries
    FILE: run.rs lines 416-442

  No Pearl Gateway:
    fetch_pearl_gateway_mining_job fails -> warning logged ->
    "could not derive Pearl merge job inputs from candidate; skipping"
    No work is ever mined because sigma (Pearl header) is unavailable,
    making kappa derivation impossible.
    FILE: run.rs lines 518-525

  No --mining-pkh:
    Binary exits with code 1 at startup before connecting to anything.
    FILE: ai_pow_mine.rs lines 113-116

DATA FLOW BETWEEN THE THREE PROCESSES:

  Nockchain node  --[%mine-ai candidate: block_header, target]--> ai-pow-mine
  Pearl Gateway   --[getMiningInfo: incomplete_header, aux_inclusion]--> ai-pow-mine
  ai-pow-mine     --[matmul + ZK proof]--> Nockchain node (%ai-pow poke)
  ai-pow-mine     --[submitPlainProof]--> Pearl Gateway (Pearl block reward)

Pearl's vLLM plugin runs Pearl's normal AI inference workload AND exposes the
Gateway socket as a side effect. The ai-pow-mine binary attaches to that socket
as a second client alongside whatever Pearl-native miners Pearl runs internally.
Pearl's miners earn Pearl rewards; ai-pow-mine additionally earns Nockchain
rewards from the same matmul work.
